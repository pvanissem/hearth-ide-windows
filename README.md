# Hearth IDE for Windows

Windows companion to [Hearth IDE](https://github.com/pvanissem/hearth-ide) (native macOS/SwiftUI).
The macOS app cannot be compiled for Windows (SwiftUI, AppKit, Seatbelt and the Keychain are
macOS-only), so this is a separate Electron client that keeps the same ideas and ports the
platform-independent logic: agent catalog, sandbox policy, inbox status and Git handling.

## What works (v0.1)

| Area | macOS app (v0.8.0) | This client |
|---|---|---|
| Agents: Claude Code, Codex, Copilot CLI, OpenCode, Gemini, shell | yes | yes (catalog, resume and login arguments ported) |
| Terminal in the chat area (PTY, ConPTY) | SwiftTerm | xterm.js + node-pty |
| Inbox with status (running / needs input / idle / done) | hooks, notify, terminal | terminal heuristics + bell, desktop notification |
| Sandbox | nono + Seatbelt | nono inside WSL2 (see below) |
| File tree and editor | Monaco | Monaco, workspace-restricted, `.git/hooks` write-protected |
| Git: status, diff, stage, commit, history | sandboxed Git | host Git with hooks and fsmonitor disabled |
| Settings: domains, ports, SSH for Git | yes | domains, ports, SSH, unsandboxed opt-in |
| Search Everywhere, Architecture (Mermaid), CI/CD, Build & Deployment, Journal, themes, German UI | yes | not yet |

## Sandbox on Windows

[nono](https://github.com/nolabs-ai/nono) supports Windows only through WSL2. Agents are started as

```
wsl.exe -d <distro> -e bash -lc "cd /mnt/c/... && exec nono run --profile <profile.json> -- <agent>"
```

with a profile generated by `src/main/policy.js` (writes only to the project folder, the run folder
and a private per-agent config folder; network only to the agent's API hosts plus your additions;
`.git/hooks` protected). **Without WSL2 and nono the app refuses to start agents.** You can opt in
to unsandboxed runs in Settings; such sessions are labelled `NO SANDBOX` in the inbox.

Setup: `wsl --install`, then install nono and your agent CLIs inside the distro.

Not yet verified on a machine with WSL2: the nono profile group names (`node_runtime`, ...) are the
macOS ones minus the `_macos` suffix and may need adjusting for Linux; agent logins that use the
macOS Keychain need another mechanism inside WSL (their own credential files in the private config
folder, or nono credential proxy routes, not ported yet).

## Develop

```
npm install
npm start          # run the app
npm test           # unit tests (paths, policy, Git parsing, status, settings)
powershell -File scripts/smoke.ps1   # drives the real app: PTY, UI, Git, editor, access checks
npm run dist       # NSIS installer via electron-builder
```

Needs Node 20+. `node-pty` ships Windows prebuilds, no compiler required.

## Security notes

- The renderer is sandboxed (`contextIsolation`, no Node); all file and Git access goes through the
  main process and is limited to folders you picked or started a session in.
- Host-side Git runs with `core.hooksPath` pointing at the null device and `core.fsmonitor=false`,
  so repository-controlled code is not executed outside the sandbox.
- Settings live in `%USERPROFILE%\.hearth\settings.json` (override with `HEARTH_HOME`).
